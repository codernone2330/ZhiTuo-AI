# 拜访任务与推荐商机后端链路

本阶段沿用现有 FastAPI、PostgreSQL、JWT 身份及组织范围。客户主档仍是唯一事实来源：
推荐商机是未成交客户的派生视图，不复制一张可能与 CRM 失步的商机表；拜访任务单独保存。

## 数据与接口

- `visits`：客户、负责人、预约时间、方式、目标、状态、反馈、成交金额、重复拜访授权原因及版本号。
- `GET /api/v1/opportunities`：分页读取本人可见的未成交客户推荐清单，含评分、原因、产品方向。
- `GET /api/v1/opportunities/{customer_ref}`：读取单个授权商机的推荐详情。
- `POST /api/v1/opportunities/refresh`：按当前身份与可选下级组织，重算评分和推荐原因。
- `GET /api/v1/visits`、`GET /api/v1/visits/{id}`：分页查询及详情。
- `POST /api/v1/visits`：创建任务；已有未完成任务时需至少 5 字重复创建原因。
- `PATCH /api/v1/visits/{id}`：调整时间、方式、负责人、目标和备注。
- `POST /api/v1/visits/{id}/cancel`：填写原因后取消。
- `POST /api/v1/visits/{id}/complete`：保存结果、阶段及用户填写的成交金额，同时更新客户档案。
- `POST /api/v1/visits/import`：集团管理员首次迁移原页面的拜访演示记录，按原任务编号幂等去重。

修改和结束任务必须传 `version`；旧版本返回 409，不覆盖其他人刚保存的工作。
客户被审批删除后，相关任务保留在数据库作审计记录，但不出现在普通任务列表。

## 权限与页面适配

集团和超级管理员查看全域；组织管理员查看本级及下级；部门负责人查看本部门；客户经理
仅查看本人客户且本人负责的任务。只读角色可以查看授权范围，但不能刷新商机或管理任务。
所有权限在服务端重新校验，不依赖页面按钮是否显示。

登录时页面读取客户、推荐商机与拜访任务。首次迁移仅在拜访表为空且集团／超级管理员
登录时进行；旧浏览器中未被该次迁移包含的本地拜访数据不会自动合并，需人工核对。
CRM 的“刷新共享客户”同时刷新三类业务数据。

“AI 更新商机”目前是基于已入库客户信息的可解释规则重算，不调用外部企业查询或大模型；
产品方向根据需求与行业关键词匹配，供人工核验。真实企查查增量线索采集属于另一条链路。
