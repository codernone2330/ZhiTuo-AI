# 第六、七周交付与待办

## 本次完成

第六周：将企查查模糊搜索接入现有 FastAPI 服务。采集结果仅写入 `external_leads` 待审核池，不自动进入客户库；另一位具有经营管理权限的人员批准后，才在同一数据库事务中创建客户并写入评分基线。重复企业会拦截。AI 问答改由 `/api/v1/ai/chat` 统一转发到固定的平台地址，服务端根据当前 Token 重新查询授权客户与拜访数据，最小化组装上下文，不信任前端提交的业务汇总。密钥由用户在前端配置或由服务端环境变量提供，不写入审计记录。

第七周：新增服务端周经分 `/api/v1/reports/weekly`，按中国时区自然周统计拜访、客户覆盖、成交、同比和环比，并返回可按授权客户穿透的明细。新增共享资料的上传、列表、更新、下载、操作记录，按组织树限制同级及下级读写；文件内容暂存数据库，限制 5 MB。数据管理页提供线索池、共享资料和审计入口。原有本地演示周经分仍保留，页面明确标注以上方服务端数据为准。

## 新接口

| 范围 | 接口 | 作用 |
| --- | --- | --- |
| 外部线索 | `POST /api/v1/ai/leads/capture` | 按搜索词采集到待审核池 |
| 外部线索 | `GET /api/v1/ai/leads` | 授权范围内分页查询 |
| 外部线索 | `POST /api/v1/ai/leads/{id}/decision` | 独立审核、入库或驳回 |
| AI | `GET /api/v1/ai/models` | 已允许的平台模型 |
| AI | `POST /api/v1/ai/chat` | 权限内上下文 + 模型网关 |
| 报表 | `GET /api/v1/reports/weekly` | 周汇总、同比环比与明细 |
| 审计 | `GET /api/v1/reports/audit` | 采集/审核/AI 调用元数据 |
| 资料 | `GET/POST /api/v1/documents` | 授权列表、上传 |
| 资料 | `PUT /api/v1/documents/{id}` | 乐观锁更新版本 |
| 资料 | `GET /api/v1/documents/{id}/download` | 授权下载并留痕 |
| 资料 | `GET /api/v1/documents/{id}/events` | 资料操作记录 |

数据库迁移为 `20260924_0008`。Docker 服务启动时会自动执行 `alembic upgrade head`；更新代码后需重建 API 容器。企查查凭证须在项目 `.env` 中配置 `QCC_APP_KEY` 和 `QCC_SECRET_KEY`；不应写入 HTML 或提交 Git。

## 待继续处理

1. 共享文件目前使用数据库 BLOB，尚无恶意文件扫描、对象存储、文件内容历史版本和预览；正式环境应补齐。
2. 原型页面周经分下半部分仍保留本地模拟口径，上半部分才是共享数据库权威统计；后续可逐步迁移旧组件，避免双口径长期并存。
3. 审计目前覆盖外部线索、AI 调用和文件操作。跨模块统一审计检索、下载审计告警与保留策略尚未完成。
4. AI 上下文已按后端授权范围裁剪且不自动发送联系人/电话；用户在问题中自行输入的内容仍会发送到所选模型平台。正式投产前须完成数据分类分级、脱敏、密钥托管及外部模型合规评审，不能承诺绝对不会泄露。
5. 当前 Docker 仍仅绑定本机 `127.0.0.1:8000`；跨电脑共享需要部署到受控内网或云服务器，并配置 HTTPS 与网络访问控制。
