# 身份与组织接口说明

本阶段把身份、组织和用户权限放到服务端统一判断。前端提交的组织 ID 只作为请求参数，
不能直接决定数据访问范围。

## 本地账号

仅在 `local`、`development`、`test` 环境创建初始化集团管理员。默认账号为
`groupadmin`，默认口令由 `.env` 的 `BOOTSTRAP_ADMIN_PASSWORD` 控制。共享测试前必须修改，
生产环境不会自动创建该账号。

## 身份接口

- `POST /api/v1/auth/login`：账号密码登录，返回短期 Access Token，并写入 HttpOnly Refresh Cookie。
- `POST /api/v1/auth/refresh`：用 Refresh Cookie 换取新的 Access Token。
- `POST /api/v1/auth/logout`：吊销当前刷新会话并清除 Cookie。
- `GET /api/v1/auth/me`：读取当前用户、角色和所属组织。

Access Token 默认 30 分钟有效，Refresh Session 默认 7 天有效。数据库只保存刷新凭证的
SHA-256 摘要，不保存原始 Token。

## 组织接口

- `GET /api/v1/organizations/tree`：返回当前身份可见的组织树。
- `GET /api/v1/organizations/{id}`：读取授权范围内的组织。
- `GET /api/v1/organizations/{id}/children`：读取直接下级组织。

集团管理员可见全部组织；组织管理员可见本组织和全部下级；其他角色只可见所属组织。

## 用户接口

- `GET /api/v1/users/roles`：读取可授予角色。
- `GET /api/v1/users`：分页查询授权范围内用户。
- `GET /api/v1/users/{id}`：读取用户详情。
- `POST /api/v1/users`：新增用户。
- `PATCH /api/v1/users/{id}`：更新姓名、工号、密码、组织、角色或启用状态。
- `DELETE /api/v1/users/{id}`：停用账号，不物理删除历史记录。

只有集团管理员和组织管理员可以新增、修改或停用用户。组织管理员不能操作平级或上级
组织，不能授予集团管理员角色。客户经理必须归属集客部。系统禁止停用当前登录账号，
并禁止停用最后一个有效集团管理员。

分页返回统一使用 `items/page/pageSize/total/totalPages`。

## 启动与验证

```powershell
docker compose up -d --build
```

启动后访问 `http://127.0.0.1:8000/app/` 使用系统登录页面。前端已经调用真实登录、
刷新、退出、当前身份、组织树及用户管理接口，不再将用户账号或口令保存在 localStorage。

访问 `http://127.0.0.1:8000/docs` 可单独调试接口。先调用登录接口，再点击 Swagger 的
`Authorize` 输入返回的 `accessToken`（不需要手工添加 `Bearer` 前缀），即可调试受保护接口。
