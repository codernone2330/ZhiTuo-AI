## 局域网共享部署（R03）

1. 先在**本地模式**由超级管理员逐一修改所有活动用户密码，不能使用 `szyd123456` 等演示密码。停止服务前确认管理员新密码可登录。启动脚本不会再覆盖这些新密码。
2. 备份 PostgreSQL。建议 `pg_dump -Fc` 保存带时间戳的压缩备份到 Docker 数据卷之外，并在独立测试库执行 `pg_restore` 验证。迁移前后均备份；不要执行 `docker compose down -v`。
3. 从 `.env.shared.example` 复制到本地 `.env`，为 `POSTGRES_PASSWORD`、`JWT_SECRET_KEY` 分别生成独立随机值，替换 `LAN_BIND_IP`、`SHARED_HOST`、`TRUSTED_HOSTS`、`CORS_ORIGINS`。不可直接使用样例值。**如果已有 PostgreSQL 数据卷，不能只改 `.env` 的数据库密码：需在数据库中先按 PostgreSQL 流程轮换角色密码，再更新 `.env`，并验证连接。**
4. 用 `docker compose -f docker-compose.yml -f docker-compose.shared.yml config --quiet` 校验，再以相同 `-f` 参数运行 `up -d --build`。默认 `start.cmd` 不启动共享网关。后端数据库和 Redis 仍只绑定本机；仅 TLS 网关的 8443 端口绑定指定局域网 IP。
5. Caddy 使用内部 CA。管理员应从网关容器导出根证书，经可信渠道给每台客户端安装信任，先核对证书指纹；不应点击浏览器“继续访问不安全网站”。正式跨公网部署宜改为受信任域名证书。
6. Windows 防火墙仅对“专用网络”及指定团队网段放行 TCP 8443，绝不开放 5432/6379。路由器不要做公网端口映射。分别从第二台电脑访问 `https://<SHARED_HOST>:8443/app/`，用不同角色验证权限；一台电脑写入客户，另一台刷新后能看到同一数据库的数据。记录测试日期、两台主机、角色、请求 traceId 和结果。
7. 固定周期备份并定期演练恢复；迁云前先做受控网络、域名证书、密钥管理、对象存储/数据库备份与告警设计。

## 模型联调（B03）

后端只允许固定平台 URL 和模型白名单；页面可选模型，但真实可用性取决于对应账号授权、地域和余额。当前没有向平台发起收费请求。把密钥临时放进**当前终端环境变量**，从 `backend/` 执行 `python -m scripts.check_ai_providers deepseek deepseek-v4-flash`；Qwen、GLM、Kimi 分别使用 `QWEN_API_KEY`、`GLM_API_KEY`、`KIMI_API_KEY` 环境变量与页面提供的模型标识。每次只发一条短请求，可能计费。结果只输出平台、模型、错误码及回答长度，不输出密钥。
