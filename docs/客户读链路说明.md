# 客户读链路说明

本阶段将客户主数据从单个浏览器的 `localStorage` 迁移到 PostgreSQL，完成客户导入、查询、
详情和前端数据适配。所有接口都要求登录，并在服务端执行角色与组织范围校验。

## 数据表

- `customers`：客户主档、组织归属、负责人、线索类型、经营阶段、评分和需求等。
- `customer_import_batches`：导入人、来源、总行数、新增数、重复数、拒绝数和批次状态。
- `customer_requests`：客户归属变更、删除申请和直属上级审批记录。

前端原客户编号保存在 `external_id`，数据库另有 UUID 主键。这样既能保持现有拜访记录和
页面跳转不变，又能在后端稳定建立关联。

## API

- `GET /api/v1/customers`：分页查询，可按关键词、阶段、线索类型和组织过滤。
- `GET /api/v1/customers/{customer_ref}`：按数据库 UUID 或原客户编号读取详情。
- `POST /api/v1/customers/import`：批量导入 1—1000 条客户并返回批次统计。
- `PATCH /api/v1/customers/{customer_ref}`：编辑客户主档，使用 `version` 防止覆盖他人更新。
- `POST /api/v1/customers/{customer_ref}/requests`：提交归属变更或删除申请。
- `GET /api/v1/customers/requests`：查询本人申请和待本级审批的申请。
- `POST /api/v1/customers/requests/{request_id}/decision`：直属上级通过或驳回。

分页统一返回 `items/page/pageSize/total/totalPages`。导入按原客户编号、同一组织内规范化企业
名称及联系电话去重，不自动覆盖既有档案。

## 数据范围

- 超级管理员、集团管理员：可读取全部客户。
- 组织管理员：可读取本组织及所有下级组织客户。
- 部门负责人：可读取本部门客户。
- 客户经理：只读取 `owner_user_id` 为本人，或迁移期负责人姓名与本人一致的客户。
- 只读角色：只读取所属组织客户。

导入允许超级管理员、集团管理员、组织管理员、部门负责人和客户经理；目标组织必须在本人授权范围内，
并且必须是市级或区县级集客部。客户经理只能导入本人负责的客户。只读用户不能编辑或导入。

## 前端适配

登录成功后，页面分页拉取当前用户授权范围内的后端客户。数据库为空且由集团或超级管理员
首次登录时，会将当前 HTML 中完整的演示客户迁移一次；后端去重保证重复登录不会重复写入。之后：

- CRM 列表使用后端客户数据；
- 查看详情会调用客户详情接口；
- CSV 导入直接写 PostgreSQL；
- 页面新增线索直接写 PostgreSQL；
- 客户详情编辑写入 PostgreSQL；归属变更和删除经服务端审批后生效；
- CRM 页面可点击“刷新共享客户”读取其他成员最新提交的数据；
- 不同用户连接同一个部署环境时，按照组织权限共享客户数据。

推荐商机和拜访任务现已接入后端，详见《拜访商机后端链路说明》；共享文档仍保留在前端状态中。
旧版浏览器里的本地审批记录仅为兼容保留，不会自动迁移到数据库。
